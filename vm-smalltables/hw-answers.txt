Given your understanding of how cache memory works, how do
you think memory references to the page table will behave in the
cache? Will they lead to lots of cache hits (and thus fast accesses?)
Or lots of misses (and thus slow accesses)?

Spatial locality (good for caching)
Page directory: Small (32 bytes = 1 page), so the entire page directory often fits in L1/L2 cache. Once loaded, subsequent accesses to PDEs are cache hits.

Page table pages: Each page table page is 32 bytes. A single cache line (typically 64 bytes) can hold 2 entire page table pages. So a few cache lines hold many PTEs.

Access pattern: For each virtual address translation, you access:

One PDE (within the page directory)
One PTE (within a page table page)
These are spatially close if the same page directory or page table page is accessed repeatedly.

Temporal locality (good for caching)
Repeated accesses: If a process repeatedly accesses virtual pages in the same region of its VA space, they map to PTEs in the same page table page → same cache line.
Working set: Most processes don't access all 1024 pages uniformly. They cluster accesses in a smaller working set, which means:
Only a subset of page table pages are ever accessed.
These hot page table pages remain in cache.
Misses occur only when switching to a new working set region.
